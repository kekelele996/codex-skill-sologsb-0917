# 2026-10-01 难度下限（P3）复盘：自包含的合并规格被判过于简单

## 事实

- 项目：`sologsb-1115 · 昆虫标本采集记录台`（纯前端 React + IndexedDB 标本台账）。
- 提交：submission `20713`，任务难度填「困难」，A/B 两轮都跑完，本地 `status=complete`。
- 平台结论：`qc_hit_rule=P3`、`qc_conclusion=DISCARD`，原话是“命中题目规则 P3（题目难度过于简单）：
  题目难度过于简单，不符合收录标准……本题命中 4 项……判定的题目真实难度档位为「中等」……
  该条数据作废，不可返修”。
- 平台逐项给出的依据（全部来自题面原句）：修改范围「回营地要把各自那份合并回队里的主台账」、
  上下文依赖「同一个标本编号两边都动过时，分类和采集信息认先登记的那份」、
  交互轮次「同一份记录再并一次不多出条目」、技术广度「野外调查分队离线各自记标本」。
- 平台档位说明：“自包含的合并规格，需实现冲突取舍、回滚与幂等，但无跨模块整合或架构设计。”

## 为什么本地门禁没拦住

- G16（难度论证）看的是“多模块整合、关键设计取舍、复杂技术关注点”三项是否成立。这道题三项都成立：
  产物确实跨了数据模型、持久化、既有页面和导出，也确实在冲突归属、整批回滚与幂等之间做了取舍。
- G16 三次加固（规则堆叠）看的是“是不是在同一个子系统里堆规则”。这道题的六个规则族一个都没命中，
  所以没有触发 `complexityTopology` 要求。
- G17 看的是“地狱级特征”，这道题本来就按「困难」提交，不涉及。
- 结论：三者回答的都是“够不够难”，没有一层回答“是不是一条自包含的规格、执行者要不要先读懂仓库”。
  P3 是难度下限，和 G16/G17 是不同维度，必须单独设门禁。

## 已经固化的规则

`scripts/prompt_tools.py` 新增 `P3_*`：

- 四个特征提示器 `P3_FACET_HINTS`（scope / context / rounds / breadth），命中只作提示与留痕。
- 难度论证必填块 `p3DifficultyFloor`：四项逐项 `hit`、题面原句 `promptQuote`（≥12 字，回题面核对）、
  `counter`（≥20 字反证），再加上 `repoContextDependency`、`crossModuleOrArchitecture`、
  `oneRoundEstimate` 三个问答。
- 命中合计 ≥2 项时，必须给出跨模块或跨系统证据（`modules` 与 `quote` 都要出现在题面里），
  并且 `canModelFinishInOneRound=false`；题面是自包含合并或对账规格时直接阻断。
- `validate_difficulty_review` 的返回值新增 `p3Facets` 与 `p3FacetLabels`，`prompt` 命令会在
  warnings 里列出命中的特征，方便出题人当场改题。

同时把 `corpusEvidence.nearestDiscardedId` 的可接受范围从 `G16/DISCARDED` 放宽到
`G16/G17/P3/DISCARDED`，这样以后可以直接引用 P3 废弃样本来做语料对照。

## 正确改法（本题的对照）

改硬的关键不是加更多规则，而是加第二个持有状态的端，并把这条关系写进题面：

- 题面里出现两个各自持有记录的角色或系统（例如分队那份记录与队里的编目库），改动落在两侧的连接处。
- 合并要跨两端对账：冲突字段按侧定归属，失败后按侧恢复，重复并入要能重放。
- 执行者必须先把仓库里既有的记录结构、编号规则、鉴定与柜位约束读懂才能动手。
- 改动摊到三个以上既有模块（数据结构、持久化层、既有页面入口），一轮改不完。

反例（本次被判中等的形态）：题面把“按先登记取数、保护鉴定与柜位、远坐标交人裁决、失败整批回滚、
重复并入不重复”全部写死，执行者照做即可；产物虽然改了不少文件，但所有权始终在一份台账里。

## 出题人自检

写题面前先按 `references/difficulty-standard.md` 的“P3 四问”过一遍；`prompt` 命令报出
`p3FacetHitCount ≥ 2` 时不要改难度字段，直接改题面。平台明确写了这类数据“无法返修”。
