# GSB 提交字段填写说明

本文件由 `scripts/sologsb.py gsb` 按运行时只读 schema 自动生成。填写时必须逐字
使用 `交付表.xlsx` 的同一份数据；轨迹和录屏在本地阶段填绝对路径。

- `User Prompt`：唯一提示词原文，A/B 完全相同。
- `任务类型`、`任务难度`：使用 Skill 门禁确认的枚举值。
- `语言/框架`：主要语言和框架，最多四项。
- `Harness`：`Claude Code`；`Harness 版本` 两次必须相同。
- `操作系统`：`MacOS/Linux` 或 `Windows`。
- `环境可复现等级`：按仓库真实情况选择三种官方枚举。
- `初始环境快照`：`main` 初始 commit 的 40 位永久链接。
- `A/B-SessionID`：各自轨迹中的 SessionID，必须不同。
- `A/B-轨迹文件`：本地阶段填 `.jsonl` 绝对路径；后续上传前须满足 27MB 上限。
- `A/B-产物快照`：对应 `A`/`B` 分支产物的 40 位 commit 永久链接，父提交必须一致。
- `A/B-运行录屏`：本地 `demo.mp4` 或 `failed-start.mp4` 绝对路径；上限 500MB。
- `A/B-交付完整性`：1~5 的整数，两侧独立打分，锚点见 `references/delivery-scoring.md`。
- `A/B-交付完整性描述`：40–200 个非空白字符，只写需求是否做完、代码能否运行、有没有虚假成功；5 分写核对依据，非 5 分写问题位置、模型行为和客观后果。可与 GSB 理由提同一件事，但不得照抄；A、B 两段不得雷同（G12）。
- `GSB 结论`：`A 更好`、`Same`、`B 更好`。
- `GSB 理由`：150–240 个非空白字符，A、B 两侧都要分别覆盖过程与产物。过程写轨迹中的实际动作和定位节点，产物写最终可观察结果。
- `GSB 理由` 必须严格使用纯文本，不允许任何 Markdown 语法；标题、列表、代码块、行内代码、链接、图片、强调标记、表格、引用和 HTML 标签全部阻断。
- `GSB 理由` 不得引用录屏、视频、截图、浏览器、测试设备、运行环境、验收宿主、Otty、鼠标、分辨率等场外因素，没有例外。
- `GSB 理由` 不得引用 `evaluationExcluded` 的环境或工具噪声证据。
- 禁用“闭环”“根因”“落库”；数据写入统一写“入库”。“真实”“真正”“其实”等空泛表达会给出警告。
- 句子要达到高中语文阅读水平且表达通顺，单句非空白字符不得超过 56 字；分句过多、重复标点、标点不成对和残句会阻断。
- 同一侧的事实连成一段写：相邻两句不用同一称谓起头，每侧称谓最多 3 次，不写 8 字以下碎句；结尾前交代这题最看重哪一条。
- `有效性`：环境干净且可归因时填 `有效`，否则按官方作废枚举填写。
