# 监控台提示词模板

以下内容可直接复制到监控台，只需替换 `{{selected_project}}`。监控工作目录和唯一任务名由监控台队列自动注入。该模板是操作指令，不属于提交到 GSB 的题目提示词。

```text
使用 $sologsb-0917，在监控队列提供的监控工作目录下执行一道完整的 Pair-wise GSB。仅本地交付：严禁调用 `submit --execute`，严禁调用 SOLO2 写接口。

环境要求：
- Solo Manager 必须使用 admin 对应的有效登录态；当前登录态不是 admin 时立即停止。
- 本机凭据（Claude Key、Solo Manager 账号、SOLO2 账号、GitHub Token）统一来自设备配置文件 `~/.codex/sologsb/config.json`，技能启动时自动注入环境变量，不在提示词里指定具体钥匙串条目名；禁止把明文凭据写入任务目录、状态文件、轨迹或日志。
- 配置缺失或验证不通过时先执行 `scripts/configure.py wizard` 补齐并联网验证，不要带着失效凭据继续开跑。
- 单 Key 默认全局最多同时占用 4 个候选槽位，按“两个任务、每个任务两个候选”共享名额；不得默认使用 3 个候选。
- 每个容器启动前都必须在主机级独占锁内预约槽位；上限动态读取设备配置 `~/.codex/sologsb/config.json` 的 `claude.maxContainers`（默认 4，绝对上限 8）。运行中容器与存活预占位合计超限时不启动当前容器，排队等待槽位释放，排队期间按领号顺序放行、每 5 秒重读上限；数据库、验证 clone、监控台辅助容器等非任务容器不占名额。

项目接入：
- 已选定项目：`{{selected_project}}`。
- 非空时必须使用其中的 projectCode 或 projectId 接入，不得静默换题；无法按要求接入时立即停止。
- 为空时从 Solo Manager 正式选择 `0-1 代码生成`、`困难` 项目，记录 taskId、taskNo、variant、选择结果以及选择前后的配额变化；字段缺失时写“平台未返回”，不得猜测。
- `init` 必须显式传入指向监控工作目录下唯一任务目录的 `--task-root`，不得依赖进程当前目录。
- 仅下载源码不会消耗任务配额；没有发生正式选择时，不得伪造配额消耗。

执行门禁：
- 所有候选共用同一份 UTF-8 题目提示词，字节完全一致；不得选择“代码理解”。
- 竞速阶段必须显式执行 `run --side both --candidates 2 --attempts 6 --base-url {{base_url}}`；`{{base_url}}` 取设备配置里的 `claude.baseUrl`，未提供时回退到运行环境的默认值。
- 前两个结构校验通过的候选按完成顺序映射 A/B；候选目录和候选编号不得改名。
- A/B 映射完成后才运行 `github-init`，创建 GitHub `main`、`A`、`B`。
- A/B 必须分别完成语义完成审核；两侧都通过后才允许 `publish` 原子发布产物。
- 遇到 429 `max_parallel_requests` 时先等待 Key 恢复，不得立即重启新候选；恢复后重开时仍使用新容器、新 Claude home 和新 SessionID，实际尝试次数照记。
- `end_turn` 只表示回合结束，必须结合轨迹、diff 和产物语义判断是否真的完成。
- 每个 A/B 产物必须执行真实依赖准备、测试、生产构建或启动验证；结论必须绑定轨迹、commit、命令输出或退出码。
- A/B 必须分别使用 Terminal.app（+Chrome）录制真实视频，统一 1280x720；失败也保留真实过程，禁止 headless、伪造或只录成功片段。
- GSB 理由必须让 A/B 两侧都分别覆盖过程与产物：过程写轨迹中的实际动作和定位节点，产物写最终可观察结果；草稿 claim.text 要原样进入理由，不能整段只写交付物毛病。
- A/B 交付完整性按 `references/delivery-scoring.md` 各自打 1~5 分并独立撰写描述：只谈完整性，5 分写核对依据，非 5 分写问题位置和客观后果；不得照抄 GSB 理由，两段之间也不能雷同。
- 红线：交付完整性描述必须与本侧轨迹对应，不得与本侧复核结果、GSB 理由或结论对立；本地编写的测试和自动化脚本不参与交付完整性描述；有页面的项目照常用录屏证据，纯后端 API 项目在验证计划里补 `probe` 接口探活；描述直接写“请求了xxx接口，返回404”，不写“从录屏来看”“根据编写的测试”。
- GSB 理由按“一侧一段话”写，相邻句不用同一称谓起头，结尾前交代这个任务最重要的是哪一条；题目提示词像业务方交代需求，不写成条款清单。
- 任一门禁不通过立即停止并报告准确原因；预期内的 A/B 产物失败可以继续保留失败证据，不得跳过该侧录屏。

最终交付：
- 最终回复严格使用 `references/final-delivery-format.md` 的八个二级标题，不得自行改写标题或添加讨论。
- 本地交付时，“SOLO2 推送结果”固定写“未执行（仅本地交付）”。
- Excel、字段说明、轨迹和视频均使用绝对路径；视频使用 Markdown 图片语法内嵌。
```
