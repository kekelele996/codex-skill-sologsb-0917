# 提交后质检与返修闭环

提交动作本身不算完成。只有页面出现明确的 `质检通过`，任务才可以结束。

## 终态处理

- `质检通过`：记录提交编号、质检完成时间、页面截图和结果 JSON，进入完成状态。
- `质检未通过`、`质检失败`、`质检异常`：禁止标记完成，必须进入返修。
- 超时仍未出现终态：按未完成处理，继续轮询或重新附着到已提交页面，不得用“正在质检”作为最终结果。
- 不因“数据已提交”就把任务标记为成功。

## 返修顺序

1. 从页面 `质检结论` 区域提取全部审核意见，写入 `monitor/qc-repair.json`。
2. 把每条意见映射到具体产物、轨迹、commit、视频或字段，不得猜测。
3. 返回到对应的 `sologsb-0917` task root 修复代码或数据，重新生成受影响产物。
4. 如代码或产物 commit 改变，必须重新生成视频和真实复核证据。
5. 重跑 `gsb-submit-preflight/scripts/preflight.py`，直到没有 blocker。
6. 用新的 `submission-payload.json` 重新提交。
7. 修复会改变 payload、交付表或改动量复核哈希时，原有例外审批自动失效；正常完整审核通过仍按自动批准流程处理。
8. 再次提交并等待到 `质检通过`；未通过则重复以上步骤。禁止不做修改地原样重提。

## 结果文件建议

审核意见索引：

```json
{
  "submissionNo": "179",
  "qc": "质检未通过",
  "issues": [
    {"issue": "页面审核原文", "target": "文件/轨迹/commit/视频/字段", "action": "修复动作"}
  ]
}
```

完成证据至少保留：

- 提交编号
- 最终页面文本
- 质检通过截图
- `submission-result.json`
- 更新后的 preflight 报告


## G5 理由返修口径

平台打回“过程与产物未同时覆盖”时，不能只补一句“读了文件”。A、B 两侧都要各自覆盖过程与产物：

- 过程：在哪个步骤、文件、命令或需求下，实际读取、检查、修改、执行、排查、验证或返工了什么。
- 产物：接口返回、缺少字段、未实现需求、构建启动结果、写入结果或真实失败等可观察结果。
- 对比：同侧过程动作与产物结果要形成因果链，最后再给 `A 更好` / `B 更好` / `Same`。
- 草稿中用于支撑每侧过程与产物的 `claim.text` 必须原样进入 GSB 理由。

修复骨架：

> A 侧方案在联调阶段读取 `database/init.sql` 和迁移脚本后，仍保留旧唯一约束，升级后索引列表仍含 `idx_run_input_version`；B 侧方案在新增指标时同步口径说明和默认单位，但新增、编辑和重命名流程仍未接入，提交后配置没有写入。A 侧产物保留了旧约束，B 侧流程接入不完整，A 更好。

只有每侧都出现过程事实、产物事实和最终对比，才允许重新提交。

## 2026-09-19 G5 实测打回补充

本次提交 `#1976` 的实际返修过程新增以下硬检查：

- 每条 `polarity=negative` 的草稿 claim 必须带 `objectiveConsequence`；触发节点与客观后果都要原样进入 GSB 理由。
- “客观后果”要写失败本身的结果，例如修改没有落地、构建没有包含改动、服务没有启动、接口没有返回预期结果。只写“后续通过”不算后果。
- “客观证据”至少包含一个可核对点：具体文件名、函数名、命令、报错原文、退出码、接口状态或测试输出。只写“更细”“持平”等主观比较不能提交。
- 过程与产物必须分别覆盖；录屏、视频、截图、浏览器、测试设备、运行环境、验收宿主、Otty、鼠标、分辨率、终端窗口等场外因素不得进入 GSB 理由，但轨迹中的实际执行动作必须写入过程层。
- 平台 AI 化检查会标记三位以上的机器式序号和纯命令粘贴。优先写“修改服务构造函数时”“验证阶段启动服务时”等自然触发节点；命令、报错和退出码只保留支撑事实的最短片段。
- `PENDING_FIX` 优先使用 `PUT /api/v1/gsb/submissions/{submission_id}` 原地返修并生成新版本；平台会拒绝复用同一个 A/B SessionID 再次 `POST` 创建。


## B-5 公共长片段返修

平台反馈“GSB 理由与已交付数据重复，命中 B-5 公共长片段/套模板”时：

- 保留原始审核原文、历史 submission id、相似度百分比和命中片段。
- 必须读取本次与历史记录的轨迹、commit、构建/测试/启动输出，找出两侧真实差异。
- 重写时删除公共句式，只写本次可核对的文件、命令、报错、接口结果和 A/B 行为差异。
- 不得只替换项目名、模块名或几个业务词后重新提交。
- 重写后重新运行 `prompt_dedup.py --reason` 和 `preflight.py`，非 `UNIQUE` 继续阻断。
