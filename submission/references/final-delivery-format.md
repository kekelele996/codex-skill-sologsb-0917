# 最终交付展示格式（硬约束）

本模板是 `sologsb-0917` 任务完成后的唯一最终回复格式。提交到 SOLO2 后仍使用同一格式，只补全
“SOLO2 推送结果”，不得另写摘要、说明、工具日志或额外章节。

## 强制规则

1. 最终回复必须且只能包含以下八个二级标题，顺序不得调整，标题文字必须完全一致：
   - `## 仓库与初始快照`
   - `## A / B 会话、提交与轨迹`
   - `## 审核结论`
   - `## GSB 文案`
   - `## Excel 与字段说明`
   - `## 两段视频`
   - `## SOLO2 推送结果`
   - `## 未解决问题`
2. 正文不得增加前言、结束语、执行过程、命令清单或模板外补充。
3. 所有本地文件必须使用绝对路径并做成可点击链接；视频必须使用绝对路径的 Markdown 图片语法内嵌。
4. A/B 两项必须分别列出 SessionID、commit SHA、提交链接和轨迹的绝对路径。
5. `审核结论` 必须分别说明 A、B 的真实结果和交付完整性分数，逐字引用 Excel 中的交付完整性描述，并链接对应的 `审核结论-a.md`、`审核结论-b.md`。
6. `GSB 文案` 必须引用最终 Excel 中的逐字理由，不得改写。
7. `Excel 与字段说明` 必须明确 Excel 为 23 字段，并链接交付表与字段说明。
8. 两段视频必须列出时长、分辨率、成功/失败结论，并分别内嵌 A、B 视频。
9. 未提交时，`SOLO2 推送结果` 固定写 `未执行（仅本地交付）`；提交后必须写 submission id、质检终态和 API 结果路径。
10. 没有未解决问题时，`未解决问题` 固定写 `无`；有则逐条写事实、原因和影响，不得省略。
